# Benchmark plan

## Principles
- Same save, same build type, same config file, machine idle; report **median and p99** over
  ≥10 windows of 600 frames, discard the first 2 windows (level entry is measured separately).
- One change per comparison; A/B binaries run alternately (A B A B).
- Every number in docs names its command, config and commit.

## Instruments (exist today)
- Engine log `* vk stats` every 600 presents: ms/frame, p99, GPU ms (timestamps), submits, waits,
  query polls, draws, rendering scopes, program binds, draw-preparation ms (`vkDXGI.cpp`).
- `* vk memory`: VMA usage per heap vs budget, live allocations by kind.
- `tools/pmp.sh <pid>`: eu-stack sampling of the main thread (no root, perf not installed).
- `XR_VK_SCREENSHOT=<png> XR_VK_SCREENSHOT_FRAME=<n>`: frame capture for image comparisons.
- `-ltx user_bench.ltx` (windowed 1280x720, overrides) — generated by `tools/make_fixture_gamma.py`.

## Missing instruments (add in phase 1-2)
- `tools/bench.sh` in the repo (today only in a scratch directory).
- Tracy zones (engine + backend).
- Level-entry metric: time from `-start` to the first frame and p99/max frame of the first 30 s.
- GPU pass breakdown (timestamps per rendering scope or RenderDoc/Nsight captures) **[E]**.

| ID | Scenario | Config | Metric | Baseline (2026-11-25/27) |
|---|---|---|---|---|

| B3 | Level entry | B1 config | time to first frame; p99 of first window | 93 s to 600 in-level frames; p99 2.9 s |

| B8 | AMD iGPU (RADV) | B1 | as B1 | **not measured** |
